# ปุ่มดำเนินการและตัวโหลดกลาง

คำยืนยัน D42 วันที่ 16 ตุลาคม 2026

## พฤติกรรม

- หน้าผลเหลือปุ่ม “ประเมินวัดซ้ำ” ปุ่มเดียวสำหรับเริ่มรอบใหม่ แสดงเฉพาะผลล่าสุดที่ยังไม่ผ่าน คงการตรวจเฉพาะหน่วยไม่ผ่านและข้อมูลเดิมของหน่วยที่ผ่าน รวมประวัติ เลขรอบ และวันเวลาเดิม
- ลิงก์ดำเนินการ เช่น เปิดรอบประวัติ เปิดผัง เปิดผลล่าสุด และการเลือกไฟล์ ใช้หน้าตาปุ่ม ขนาดกระชับ พร้อมสถานะโฟกัส
- ทุกคำขอผ่าน API client ใช้ตัวโหลดกลางชุดเดียว รวมหน้ารอข้อมูล อ่านไฟล์แนบ อัปโหลด บันทึก เปลี่ยนหน้าหลังบันทึก และส่งออก Excel ข้อความ “กำลังโหลด” พร้อมตัวหมุนอยู่กลาง viewport
- ตัวโหลดใช้ token แยกงาน จึงไม่หายเมื่อคำขอหนึ่งเสร็จแต่ยังมีอีกคำขอทำงาน คืนสถานะเมื่อสำเร็จ ผิดพลาด หรือหมดเวลา คงการกันส่งซ้ำและไม่รีเซ็ตฟอร์มก่อนเปลี่ยนหน้า
- แสดงช่องเลือกผังในโหมดวัดซ้ำด้วย ไฟล์ยังอัปโหลดเมื่อยืนยันบันทึก ส่ง file ID ไปกับรอบใหม่และอัปเดต has_layout โดยไม่เปลี่ยนไฟล์ในรอบเก่า โหมดเพิ่มผังภายหลังยังใช้ได้

## การตรวจ

- P5 browser ตรวจแนบ PDF ให้รอบวัดซ้ำจากงานที่ยังไม่มีผัง ยืนยันรอบใหม่มี file ID และ has_layout ส่วนรอบเก่ายังคงไม่มีผัง
- P7 browser หน่วงรายการกับสรุป Dashboard แยกกัน ยืนยันมีตัวโหลดเพียงหนึ่งชุด อยู่กลางหน้าจอ และไม่ปิดจนทั้งสองคำขอเสร็จ รวมการปิดเมื่อ API ผิดพลาด
- submit-flow-check หน่วงการบันทึกและการเปลี่ยนหน้า ตรวจโฟกัส การกด Enter ไม่ส่งซ้ำ และไม่กระพริบกลับขั้นแรก ครอบคลุมฟอร์มสิ่งแวดล้อม สุขภาพ และความพึงพอใจ
- ใช้ฐานข้อมูลและไฟล์ทดสอบแยก ไม่ deploy และไม่แก้ข้อมูลจริง
