# Area กรอกค่าเฉลี่ยและค่าต่ำสุดโดยตรง

16 ตุลาคม 2026 — D40

เจ้าของงานยกเลิกจุดย่อยของ Area ทั้งในฟอร์มและรายงาน ข้อนี้แทนแนวทางเก็บ samples ที่เสนอไว้ใน P0/D08/D13 ก่อนหน้า

## การเปลี่ยนแปลง

- ฟอร์ม Area มีสถานที่ เกณฑ์ ค่าเฉลี่ยพื้นที่ (Lux) ค่าต่ำสุดพื้นที่ (Lux) และหมายเหตุ ไม่มีเพิ่ม/ลบจุดย่อยหรือช่องจุดย่อย
- รับค่าเฉลี่ยและค่าต่ำสุดเป็นตัวเลข finite ไม่ติดลบ โดยค่าต่ำสุดต้องไม่เกินค่าเฉลี่ย และเปรียบเทียบเกณฑ์เดิมทั้งสองค่าเมื่อเกณฑ์นั้นกำหนดขั้นต่ำ
- Create/correction/retest ใช้ average_lux/minimum_lux โดยตรง เก็บใน snapshot JSON เดิม ไม่เพิ่มตาราง/คอลัมน์ฐานข้อมูล
- วัดซ้ำเฉพาะพื้นที่ไม่ผ่าน ล็อกจุดพื้นที่/เกณฑ์เดิมและล้างค่าเฉลี่ย/ค่าต่ำสุดเพื่อให้กรอกค่ารอบใหม่ ห้ามนำค่าจากร่างเก่ามาเติมแทนช่องที่ผู้ใช้ล้าง
- เอาตารางจุดย่อยออกจาก review/result รวมถึงชีตฟอร์มหลักใน Excel ซึ่งแสดงหนึ่งแถวต่อพื้นที่/รอบพร้อมค่าเฉลี่ยและค่าต่ำสุด
- ข้อมูลเก่าและประวัติ samples ไม่ถูกแก้หรือลบ Server ยังอ่าน snapshot เดิมได้ และเก็บใน source/audit ซ่อนเพื่อรักษาข้อมูลต้นฉบับ ตอนแก้ไขแสดงค่ารวมเดิมที่บันทึก ส่วนวัดซ้ำสร้างรอบใหม่ด้วยค่าโดยตรง
- ร่างเก่าบนเบราว์เซอร์ที่มีข้อมูลครบแปลงเป็นค่ารวมเพื่อแสดงในฟอร์ม ไม่สร้างจุดย่อยใหม่ และไม่เขียนทับ source เก่า
- ไม่เปลี่ยน Spot/เสียง/ความร้อน ไม่ deploy

## ตรวจสอบ

- P5 unit 12 ผ่าน รวม direct input boundary, min > average, missing/mixed inputs, ร่างเก่าคงเดิม และล้างค่ารอบใหม่ไม่ fallback ไปค่าเดิม
- Domain/SQLite 23 ผ่าน; P7 unit 11 ผ่าน; frontend/Worker typecheck และ scoped ESLint/diff check ผ่าน
- P5 browser 16 ผ่าน รวมสร้าง Area ด้วยค่าโดยตรง/ไม่มีจุดย่อย/วัดซ้ำโดยต้องกรอกครบสองค่า
- P7 browser 16 ผ่าน รวม Area จากข้อมูล samples เก่า → retest แบบ direct สำเร็จ และตรวจ old.units/old.result ตรงเดิม รายงาน/Excel ไม่มีแถวจุดย่อยในชีตฟอร์มหลัก
