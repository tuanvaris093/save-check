# คืนกล่องคำแนะนำและจัดเอกสารมาตรฐาน

วันที่: 15 ตุลาคม 2026 · สถานะ: done · ยังไม่ deploy

ตามภาพและคำยืนยันล่าสุดของเจ้าของงาน:

1. แสดงหัวข้อ “คำแนะนำ” ตามด้วยกล่องพื้นเทาแบบเดิม
2. ใช้ประโยคแนะนำเดิมตามผลตรวจ แล้วต่อท้ายประโยคด้วยข้อความที่เจ้าของงานให้ไว้ใน requirement ภายในกล่องเดียวกัน
3. แสง Spot แสดงจำนวนจุดที่ไม่ผ่านจากผลปัจจุบันจริง; Area ใช้จำนวนพื้นที่ที่ไม่ผ่าน ไม่รวมจุดย่อยเป็นจุดตรวจแยก
4. วางชื่อมาตรฐานแสง/เสียง/ความร้อนใต้กล่องคำแนะนำ แล้วแสดงปุ่มดูในหน้า เปิดเอกสาร และดาวน์โหลด PDF
5. เอา description/ข้อความอธิบายเอกสารออก เอกสารยังดูได้เมื่อกดปุ่มตามเดิม

ใช้เหมือนกันในหน้ากรอกค่าที่ประเมินได้แล้ว หน้าทบทวน และหน้าผลสภาพแวดล้อมทั้งสามหมวด ไม่มีการเปลี่ยนเกณฑ์หรือคะแนนบน Worker

## การทดสอบ

ESLint เฉพาะไฟล์ที่แก้และ frontend typecheck ผ่าน `npm run test:p5:browser` ผ่าน 16 scenarios กับ Chromium/Worker/D1/R2 แยกจากข้อมูล development ไม่มี page errors หรือ foreign-key violations

เพิ่ม assertions ว่าหัวข้อคำแนะนำอยู่ก่อนชื่อมาตรฐาน มี paragraph เฉพาะกล่องคำแนะนำหนึ่งชุด พื้นเทา/ขอบเขตอยู่ในการ์ด ข้อความต่อท้ายตรงข้อความที่ยืนยันใน REQUIREMENTS_V3.md และประโยคเดิม/จำนวนจุดไม่ผ่านตรง snapshot รอบที่กำลังแสดง รวมตรวจซ้ำและ Area พร้อมปุ่ม/ไฟล์ PDF เดิม

ตรวจกล่องผลที่บันทึกจริง 14 สถานะ ครบผ่าน/ไม่ผ่านของแสง Spot, แสง Area, เสียง และความร้อน รวมจำนวนจุดไม่ผ่านจาก 2 → 1 → 0 ในการตรวจซ้ำ และตรวจหน้าทบทวนก่อนส่งด้วย ตรวจภาพจริง [Area mobile](./baseline/p5-area-mobile.png) และ [ความร้อน desktop](./baseline/p5-heat-desktop.png) แล้ว
