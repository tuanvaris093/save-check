## Cutover / rollback

1. ตรวจ candidate และ source/artifact manifest ให้ตรงกัน
2. Deploy Worker พร้อม `RELEASE_MAINTENANCE=1` เพื่อหยุดทุก API ก่อน snapshot; ตรวจ 503/Retry-After จริงก่อน migrate
3. Export cutover backup ใหม่และบันทึก recovery point ตรวจ schema/ledger จากฐานจริง ไม่ seed/truncate
4. Apply additive migrations ตามลำดับ แล้ว export/เทียบ original fields ด้วย `scripts/p9-verify-backup.py` ก่อนเปิดเขียน
5. Deploy Worker โหมดปกติ ตรวจ schema/API/CORS และไฟล์เดิม จากนั้น deploy Pages ด้วย artifact ที่ตรวจแล้ว
6. Smoke test production แบบอ่านและเปิดหน้าฟอร์ม ไม่สร้างข้อมูลทดสอบปนฐานจริง; flow เขียนทดสอบใน staging แยกแล้ว
7. หากต้องหยุดระบบ ให้ deploy Worker v3 เดิมพร้อม maintenance=1 เพื่อรักษาฐานหลัง migrate ห้ามย้อน old Worker เปิดเขียนฐาน v3 หรือ restore ฐานเก่าทับงานใหม่
8. Recovery แบบเต็มต้องสร้างฐานแยก/restore จาก backup แบบ bound rows และตรวจข้อมูล แล้วจึงสลับ binding หลังจัดการข้อมูลหลัง recovery point ไม่ใช้ DROP rollback อัตโนมัติ
