# ปรับ loading และการเปลี่ยนหน้าหลังบันทึก (D27)

วันที่: 15 ตุลาคม 2026 · ยังไม่ deploy

## สาเหตุและพฤติกรรมใหม่

เดิม clearDraft ล้างทั้ง storage และ state ทำให้ currentStep กลับเป็น 1 ก่อน router เปลี่ยนหน้า อีกทั้ง finally ปิด busy ทันทีหลังสั่งเปลี่ยนหน้า จึงเห็นหน้าฟอร์มกระพริบระหว่างทาง

ปัจจุบันลบร่างหลังได้รับผลยืนยันสำเร็จ โดยคง state หน้าสรุปจน unmount และคง lock/busy ระหว่างเปิดหน้าผล ไม่มีการหน่วงเวลาปลอม ไม่ยืนยันสำเร็จก่อน API ตอบ

ใช้ร่วมกันทั้งสุขภาพ สภาพแวดล้อม และความพึงพอใจ:

1. กดส่ง → loading “กำลังบันทึก” (มีสถานะอัปโหลดไฟล์สำหรับสภาพแวดล้อม)
2. ได้ผลยืนยันสำเร็จ → “บันทึกสำเร็จ / กำลังเปิดหน้าผลการประเมิน…”
3. เปลี่ยนหน้าผล โดยหน้าสรุปไม่ย้อนกลับขั้นแรก
4. หากส่งไม่สำเร็จ → ปิด loading และปลดล็อกให้แก้ไข/ลองใหม่ คงคำตอบและ idempotency key เดิม

Overlay เป็นกล่องกลางจอ รองรับมือถือ มีสถานะประกาศสำหรับ screen reader, focus ภายในระหว่างส่ง, ป้องกัน Enter/Tab ทำให้ส่งซ้ำ และคืน scroll/focus เมื่อปิด ไม่มีปุ่มซ่อนอยู่ใต้ overlay ที่ยังใช้ keyboard ส่งได้

## การทดสอบ

เพิ่ม scripts/submit-flow-check.mjs ใน browser suites ทั้งสาม หน่วงผลตอบกลับ API และ request เปิดหน้าผลแยกกันเพื่อตรวจสถานะ saving/redirecting จริง ตรวจ focus/Enter, POST ครั้งเดียว, MutationObserver ไม่พบขั้นตอนที่ 1 ระหว่างส่ง, หน้าสรุปยังอยู่หลังลบร่าง และเก็บภาพใน baseline/submit-flow-{health,environment,satisfaction}.png

- P4 browser 10 + P3 browser 11 scenarios ผ่าน
- P6 browser 11 scenarios ผ่าน รวม failure/retry/ร่างและการส่งจริง
- P5 browser 16 scenarios ผ่าน; ปรับกรณีทดสอบแก้ไขข้อมูลผลผ่านให้เปิด edit URL โดยตรง เนื่องจาก D26 ซ่อนปุ่มวัดซ้ำเมื่อผ่านแล้ว (ไม่ได้คืนปุ่มในสินค้า)
- Frontend typecheck และ ESLint ไฟล์ที่แก้ผ่าน
- ตรวจภาพ loading มือถือแล้ว ไม่มีกรอบ focus ทำให้มุมกล่องเสียรูป

ไม่มี deploy, migration หรือเปลี่ยนฐานข้อมูลจริงในงานนี้
