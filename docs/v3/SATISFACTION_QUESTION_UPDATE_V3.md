# อัปเดตคำถามความพึงพอใจจากเอกสารล่าสุด

วันที่ 12 ตุลาคม 2026 · งานแทรกหลัง P4 ก่อน P5 · เสร็จแล้ว · ไม่ deploy

ต้นฉบับ: แบบสอบถามความพึงพอใจ 2 ด้าน.docx ที่เจ้าของงานส่งในแชต; source path/hash และข้อความดิบใน [หลักฐานต้นฉบับ](./catalogs/satisfaction-source-docx.json)

ไฟล์ระบุสองกลุ่ม กลุ่มละ 16 ข้อ ใน 4 ด้าน: Content, Design, Usability, Usefulness และคะแนน 1–5 เช่นเดิม ปรับคำถามและชื่อด้านตามนี้ โดย normalize ช่องว่างที่ตัดกลางคำ และแก้ health q12 “ชัดเจ” เป็น “ชัดเจน” เท่านั้น; ไม่เปลี่ยนเงื่อนไขข้อมูลผู้ตอบ/ระยะเวลาที่ตกลงไว้เดิมจากคำขอที่ระบุเฉพาะคำถาม

## Implementation

- Shared catalog แยก environment/health; form เลือกตาม route group; internal key accuracy คงเดิมเพื่อรักษา API/DB แต่ label ใหม่เป็น Content
- Worker บันทึก questionnaire version แยกกลุ่ม พร้อม snapshot ข้อความ/ชื่อด้าน; legacy shared version และคำถามเดิมคงไว้สำหรับประวัติ
- Result ใช้ข้อความที่บันทึกใน snapshot; ไม่ใช้คำถามปัจจุบันทับผลเดิม; correction ข้ามรุ่นคำถามตอบ NEW_ASSESSMENT_REQUIRED เพื่อไม่เปลี่ยนความหมายคำตอบเดิม
- Draft key เพิ่ม questionnaire version; ร่างคำถามเก่าคงอยู่ใน key เดิมและไม่คืนค่า rating ในชุดใหม่ที่ข้อความเปลี่ยน
- Excel header คะแนนใช้หมายเลขข้อทั่วไป พร้อม group/version columns และ sheet พจนานุกรมคำถามแยกกลุ่ม/รุ่น เพื่อไม่แสดงความหมายเก่าบนคะแนนใหม่; full export pipeline อยู่ P7
- ไม่เพิ่ม migration และไม่เปลี่ยนสูตรคะแนน/จำนวนข้อ/scale; P5 และ full P6 ยังไม่เริ่มในคำขอนี้

## ผลทดสอบ

- 6 question update tests ผ่าน: เทียบ 32 ข้อกับ DOCX, 4×4/IDs/scale, group/version/snapshot, old-result preservation, versioned drafts และ workbook header/dictionary
- 5 browser/Worker local scenarios ผ่าน: ทั้งสองกลุ่มแสดงครบ 16 ข้อ, version/ข้อความที่ D1 เก็บและผลที่อ่านตรงกัน, old v3 wording/correction guard
- Regression P2 API 23 + P3 browser 11 + P4 browser 9 + domain 17 + SQLite 6 ผ่าน
- Frontend/Worker typecheck และ build 14/14 ผ่าน; lint 0 errors ตาม [หลักฐาน lint](./baseline/satisfaction-eslint-summary.json)
- หลักฐาน: [unit/Word/workbook](./baseline/satisfaction-question-update-tests.json), [browser/API](./baseline/satisfaction-browser-tests.json)

คำสั่ง: npm run test:satisfaction-questions; npm run test:satisfaction:browser (เริ่ม/หยุด localhost runtimes เอง)

### สภาพแวดล้อมในการทำงานด้านกายภาพ

Version: satisfaction-environment-v3-2026-10-12-r2

**ด้านเนื้อหาของแอปพลิเคชัน (Content)**

- q1: เนื้อหาเกี่ยวกับการประเมินสภาพแวดล้อมในการทำงานด้านกายภาพในแอปพลิเคชันมีความถูกต้อง ครบถ้วน
- q2: เนื้อหาของแบบประเมินมีความน่าเชื่อถือและครอบคลุมสภาพแวดล้อมในการทำงานด้านกายภาพที่ต้องการประเมิน ได้แก่ แสงสว่าง เสียง และความร้อน
- q3: การใช้ภาษาและถ้อยคำในการสื่อสารมีความชัดเจนและเข้าใจง่าย
- q4: เกณฑ์การประเมินและการแปลผลมีความชัดเจนและเหมาะสม

**ด้านการออกแบบของแอปพลิเคชัน (Design)**

- q5: การจัดวางองค์ประกอบเมนูและปุ่มต่างๆ มีความเป็นระเบียบและเหมาะสม
- q6: การจัดรูปแบบตัวอักษร ขนาด และสีของหน้าจอของแอปพลิเคชันมีความชัดเจน อ่านได้ง่าย
- q7: แอปพลิเคชันสามารถแสดงผลและตอบสนองการใช้งานได้อย่างรวดเร็ว
- q8: แอปพลิเคชันมีการออกแบบที่สวยงามและเหมาะกับกลุ่มผู้ใช้งาน

**ด้านการใช้งานของแอปพลิเคชัน (Usability)**

- q9: แอปพลิเคชันมีการจัดลำดับขั้นตอนการใช้งานที่ต่อเนื่อง เข้าใจง่ายและไม่ซับซ้อน
- q10: การประมวลผลและการเข้าถึงข้อมูลภายในแอปพลิเคชันมีความรวดเร็ว
- q11: สามารถใช้งานได้ดีทั้งในโทรศัพท์มือถือและอุปกรณ์อิเล็กทรอนิกส์อื่น ๆ
- q12: แอปพลิเคชันสามารถแสดงผลการประเมินได้อย่างถูกต้องและชัดเจน

**ด้านประโยชน์ของแอปพลิเคชัน (Usefulness)**

- q13: แอปพลิเคชันช่วยให้การประเมินสภาพแวดล้อมในการทำงานด้านกายภาพสะดวกมากขึ้น
- q14: แอปพลิเคชันช่วยลดระยะเวลาในการเก็บข้อมูลและประเมินสภาพแวดล้อมในการทำงานด้านกายภาพ
- q15: แอปพลิเคชันช่วยให้สามารถทราบผลการประเมินได้อย่างรวดเร็ว
- q16: แอปพลิเคชันสามารถนำไปใช้เป็นเครื่องมือในการประเมินสภาพแวดล้อมในการทำงานด้านกายภาพได้
