# สุขภาพด้านแสง: ทำส่วนก่อนและหลังครบก่อนบันทึก (D23)

วันที่: 15 ตุลาคม 2026 · done · ยังไม่ deploy

เจ้าของงานยกเลิกการบันทึกส่วนก่อนแล้วรอทำส่วนหลังภายหลัง (D22)

## Flow ปัจจุบัน

1. กรอกข้อมูลส่วนตัวและข้อมูลปฏิบัติงาน/เรียน รวมชั่วโมงวันนี้ในขั้นตอนที่ 2
2. ตอบก่อนปฏิบัติงาน/เรียนให้ครบ 10 ข้อ
3. กด “ประเมินหลังปฏิบัติงาน/เรียน” และตอบส่วนหลังให้ครบ 10 ข้อ
4. ดูผลสรุป ตรวจทาน และยืนยันบันทึกผลผ่าน API ผลสำเร็จปกติ

แก้คำตอบก่อนยืนยันได้ แต่ไม่มีปุ่มข้าม/บันทึกค้าง ไม่มีตารางรอทำต่อหรือปุ่มเปิดทำต่อจาก Dashboard ไม่มีการสร้างคะแนนสำหรับคำตอบหลังที่ยังไม่ครบ

## การปรับระบบ

- ลบปุ่มข้ามและคำอธิบายการบันทึกค้าง, ตารางรอทำต่อ และ API client ของ flow เดิม
- ยกเลิกการโหลดร่าง server ใน hook สุขภาพ ลิงก์ที่มี pending เดิมแสดงคำแนะนำให้เริ่มแบบประเมินใหม่ ไม่โหลดคำตอบหรือเปิดประเมินต่อ
- API health-light-drafts ทุก method/path รวม complete ตอบ HTTP 410 / WORKFLOW_RETIRED ก่อนอ่าน/เขียนข้อมูล
- ไม่ลบตาราง/ข้อมูลร่างเดิม ไม่ใช้ร่างเดิมในสถิติผลสำเร็จ และไม่รัน migration
- คงการป้องกันข้อมูลหายระหว่างกรอกในเบราว์เซอร์และ retry การส่งผลครบ 20 ข้อ; การเก็บร่างอัตโนมัติไม่ได้ส่งเป็นรายการรอทำต่อบนระบบ
- ชุดคำถาม คะแนน และฟอร์มหมวดเสียง/ความร้อนใช้กติกาปัจจุบันเหมือนเดิม
- test:health-pending เดิมชี้ไปทดสอบการยกเลิก flow กับ P4 browser แทน ชุด D22 เดิมเป็นหลักฐานในอดีตและไม่ใช้ยืนยันพฤติกรรมปัจจุบัน

## ผลทดสอบ

- P4 browser 10 scenarios + P3 browser 11 scenarios ผ่าน: API เดิมทั้ง list/save/read/complete ได้ 410, ไม่มีรายการรอทำต่อบน Dashboard, pending URL เปิดต่อไม่ได้, ไม่มีปุ่มข้าม, กั้นส่วนหลังจนก่อนครบ และกั้นสรุปจนหลังครบ, บันทึกครบ 20 ข้อได้จริงและ retry ไม่ซ้ำ
- P4 unit 8 scenarios ผ่าน รวม 20 คำตอบแยกก่อน/หลัง, valid zero, ข้อมูลประกอบและกติกาแต่ละหมวด
- Frontend/Worker typecheck ผ่าน; lint 0 errors / 74 warnings เดิม; diff check ผ่าน
