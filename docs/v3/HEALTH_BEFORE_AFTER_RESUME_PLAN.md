# บันทึกส่วนก่อนและกลับมาประเมินส่วนหลัง

> ยกเลิก flow นี้ตามคำสั่งเจ้าของงาน D23 วันที่ 15 ตุลาคม 2026 ปัจจุบันต้องทำก่อนและหลังให้ครบก่อนบันทึก ไม่มีข้าม/รายการรอทำต่อ ดู [ข้อกำหนดปัจจุบัน](./HEALTH_COMPLETE_BEFORE_AFTER_REPORT.md) เนื้อหาด้านล่างเก็บเป็นประวัติงานเดิม

วันที่: 15 ตุลาคม 2026 · สถานะ: done · ยังไม่ deploy

เจ้าของงานต้องการตอบส่วน “ก่อน” ของอาการทางสุขภาพด้านแสงให้เสร็จ แล้วข้ามส่วน “หลัง” ไปก่อน สามารถย้อนกลับ/ทำต่อ และเปิดกลับจาก Dashboard ได้

## ข้อความเสนอใช้

| ตำแหน่ง | ข้อความ |
| --- | --- |
| ปุ่มไปตอบหลังทันที | ไปประเมินหลัง |
| ปุ่มพักและกลับ Dashboard | บันทึกไว้ทำภายหลัง |
| สถานะใน Dashboard | รอประเมินหลัง |
| ปุ่มเปิดจาก Dashboard | ทำแบบประเมินต่อ |
| ข้อความหลังบันทึกสำเร็จ | บันทึกส่วนก่อนเรียบร้อยแล้ว สามารถกลับมาประเมินส่วนหลังได้จาก Dashboard |
| ก่อนส่งเมื่อยังตอบหลังไม่ครบ | กรุณาตอบส่วนหลังให้ครบก่อนสรุปผล หรือบันทึกไว้ทำภายหลัง |

## พฤติกรรมที่เสนอ

- ข้อมูลส่วนตัว การปฏิบัติงาน/การเรียน บริบท และคำตอบก่อน 10 ข้อต้องครบก่อนพักไปทำภายหลัง
- เก็บคำตอบส่วนหลังที่กรอกไปบางข้อไว้ด้วย ไม่เติมคะแนน 0 ให้อัตโนมัติ
- ระหว่างรอส่วนหลังไม่แสดงคะแนนหลัง/ผลต่าง/ระดับอาการ และไม่นับในสถิติผลสำเร็จหรือรายงานผลฉบับสมบูรณ์
- เมื่อเปิดต่อ ให้เปิดส่วนหลังและโหลดข้อมูลส่วนก่อนครบ สามารถย้อนกลับตรวจข้อมูลก่อนสรุปผลได้
- เมื่อตอบครบ จึงทบทวนและบันทึกผลตามสูตรปัจจุบัน รายการรอทำต่อหายไปและเชื่อมเป็นงานสำเร็จครั้งเดียว
- รักษาร่างเมื่อ API ล้มเหลว รองรับ retry โดยไม่สร้างซ้ำ และตรวจความขัดแย้งเมื่อข้อมูลถูกแก้จากอีกหน้าหรือเครื่อง

## คำยืนยันเรื่องที่เก็บข้อมูล

เจ้าของงานยืนยันแล้ว: **“เก็บบนระบบ เปิดต่อข้ามเครื่องได้ (แนะนำ)”** ใช้แนวทางบนระบบด้านล่าง ไม่ใช้ localStorage เป็นแหล่งหลักสำหรับรายการรอทำต่อ

โค้ดปัจจุบันมี autosave ใน localStorage; Worker รับแบบสุขภาพที่มีคำตอบก่อนและหลังครบเท่านั้น จึงต้องแยกรายการที่ยังไม่เสร็จออกจากผลสำเร็จ ไม่ส่งคำตอบหลังที่ขาดเข้า API ผลฉบับสมบูรณ์และไม่สร้างคะแนนสมมติ

## แผนเก็บบนระบบ — ทำครบแล้ว

1. เพิ่ม shared contract สำหรับร่างด้านแสง: ข้อมูลพื้นฐานครบ คำตอบก่อนครบ และคำตอบหลังบางส่วนได้
2. เพิ่มพื้นที่เก็บร่าง/สถานะรอแยกจาก submissions ที่เสร็จแล้ว พร้อม API create/read/update, version สำหรับกันเขียนทับ และ idempotency
3. เพิ่มปุ่มพักในแบบประเมินและโหลดร่างจาก URL ของรายการ รักษาร่างเมื่อเครือข่ายผิดพลาด
4. เพิ่มตารางรายการรอทำต่อบน Dashboard ตามสไตล์เดิม โดยไม่รวมรายการเหล่านี้ในคะแนน/สถิติผลสำเร็จ
5. เมื่อส่งครบ ใช้การบันทึกผลเดิมและเชื่อมร่างเป็นงานสำเร็จอย่างปลอดภัย ป้องกันส่งซ้ำ/ส่งจากฐานข้อมูลเก่า
6. ทดสอบก่อน→พัก→Dashboard→เปิดต่อจาก browser context ใหม่→หลัง→ทบทวน→บันทึก รวม partial-after, refresh, API failure, retry, concurrent update และสถิติไม่ปนร่าง

กรณีเลือกเก็บเฉพาะเครื่อง จะใช้รายการร่างใน localStorage และระบุบน Dashboard ว่าเป็นร่างในเครื่องนี้ โดยไม่ทำให้เข้าใจว่าข้อมูลบันทึกอยู่บนระบบแล้ว

เจ้าของงานเลือกเก็บบนระบบ จึงไม่ได้ใช้ทางเลือกเฉพาะเครื่อง ผลงานและหลักฐานทดสอบอยู่ใน [รายงานปิดงาน](./HEALTH_BEFORE_AFTER_RESUME_REPORT.md)
